# 04 — UX

## Purpose

Ensure flows are understandable, low-friction, and consistent — separate from pure visual styling.

## Status

`ACTIVE | N/A | PROJECT-SPECIFIC` → default: `PROJECT-SPECIFIC`


## When this module applies / when to skip

- Applies: any flow that humans complete (onboarding, forms, checkout, settings, admin tools).
- Skip / `N/A`: pure infrastructure with no human flow.
- Applies to empty states, errors, loading, and permissions messaging.

## Hard rules (MUST / MUST NOT)

- MUST design for the primary user job first; secondary tasks stay secondary.
- MUST make destructive actions reversible or confirmed.
- MUST show clear empty, loading, success, and error states.
- MUST NOT hide critical information behind unexplained icons alone.
- When Settings (or similar) lets users change the **app identity icon**, MUST follow `17-branding-and-icons.md` for pack UX, default fallback, persistence, and accessibility — do not invent the changeable-icon flow here.
- MUST keep form asking progressive: don’t demand optional data early.
- Use conversational copy for product UI: short, precise, formal. Arabic product copy is Modern Standard Arabic. Do not ask for a tone unless the user asks for a different one.
- MUST write user-facing product copy short and precise: cut AI-sounding filler and brochure adjectives; omit redundant CTAs the control already implies; MUST NOT use dialect for Arabic product UI; MUST NOT glue unrelated verbs into one button label; MUST NOT describe removed or leftover features.
- When drafting or rewriting product UI copy, MUST apply the `conversational-copy` skill (`.cursor/skills/conversational-copy/`).
- MUST NOT create dead ends without a next action.
- When the current flow cannot be completed from the existing product, ask one question.
- Prefer accessibility basics: labels, focus order, contrast sufficient for the project’s standard.
- Product layout direction for Arabic and other right-to-left locales is owned by `03-ui.md`. Conversation Arabic mixed-script display in `00-core.md` does not set that direction.

## Question protocol

Ask from this file only when the current task needs this module and the repo does not already show the answer. Follow `templates/question-protocol.md`: one short line in the user's language, and the option list only after «عرض خيارات» or "Show options". Store an Arabic answer in English. Do not add a fill-in setting in this file.

## New-project workflow

1. Name the primary user job in one sentence.
2. Map happy path + top failure path.
3. Ask flow-shape and feedback questions if unclear.
4. Use the empty, loading, success, and error states already required above. Do not open a convention questionnaire.
5. Implement flows; verify no dead ends.

## Existing-project workflow

1. Walk critical journeys in the current app.
2. List friction, confusion, and inconsistent patterns.
3. Fix journey-level issues before polishing microcopy alone.
4. Preserve muscle memory unless redesign was explicitly approved.

## Post-change checklist hooks

- [ ] Happy path completable
- [ ] Error/empty/loading states present
- [ ] Destructive actions confirmed/reversible as required
- [ ] Copy matches project voice
